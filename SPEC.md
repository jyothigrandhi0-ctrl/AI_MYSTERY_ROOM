## 1. Project overview

AI Mystery Room is an interactive web application where users become detectives and solve fictional mysteries generated by artificial intelligence.

Users enter a short story or scenario. Gemini AI transforms that input into a complete fictional investigation featuring suspects, evidence, clues, and one predetermined culprit.

The user examines the evidence, identifies the culprit, and receives an explanation of the correct solution.

### Primary objective

Build a responsive, interactive, AI-powered mystery investigation website that creates a unique playable case from each valid user scenario.

## 4. Functional requirements

### FR-01: Scenario submission

The homepage must contain a text input area for the user to describe a fictional mystery scenario.

Example:

"A valuable diamond disappears during a party at a mansion. Five guests were present, and the security camera stopped working for ten minutes."

Requirements:

- Accept 20–2,000 characters.
- Validate input before submission.
- Show a loading indicator during generation.
- Provide clear error messages for failed requests.
- Support a new investigation for each submission.

### FR-02: AI mystery generation

Gemini must generate a structured case containing:

- Unique case ID and mystery title.
- Story background and investigation setting.
- 3–5 fictional suspects.
- Exactly one predetermined culprit.
- Motives, alibis, and suspect relationships.
- 5–10 pieces of evidence.
- Timeline of fictional events.
- Explanation connecting the evidence to the culprit.

Important: The correct culprit must be determined and stored before the investigation begins. AI must not change the culprit after the user submits an answer.

- Display all suspects as selectable cards.
- Show suspect name, profile, motive, and alibi.
- Allow users to inspect evidence before selecting.
- Require confirmation before submitting the final answer.
- Prevent changing the submitted answer for the same attempt.

### FR-05: Results

After submission, the system must display the actual culprit, whether the user's selection was correct, a timeline of relevant events, and a clear explanation of the most important clues.

The solution must remain hidden until the final answer is submitted.

## 8. REST API specification

| Method | Endpoint                  | Purpose                           |
| ------ | ------------------------- | --------------------------------- |
| POST   | `/api/cases`              | Generate mystery from scenario    |
| GET    | `/api/cases/:id`          | Retrieve public case details      |
| GET    | `/api/cases/:id/evidence` | Retrieve generated evidence       |
| GET    | `/api/cases/:id/suspects` | Retrieve suspect profiles         |
| POST   | `/api/cases/:id/submit`   | Submit suspect selection          |
| GET    | `/api/cases/:id/result`   | Get result after submission       |
| GET    | `/api/history`            | Retrieve player's completed cases |

API requirements:

- Use JSON request and response bodies.
- Validate request parameters and payloads.
- Use proper HTTP status codes.
- Enforce ownership of private attempts and case results.
- Rate-limit AI generation requests.
- Never expose Gemini API credentials to the frontend.

## 11. Non-functional requirements

Performance: Provide responsive interactions, loading states, and asynchronous AI generation. Do not block the UI while the case is being generated.

Security: Validate and sanitize inputs, apply API rate limits, protect credentials, and prevent unauthorized access to solutions.

Reliability: Handle AI timeouts, invalid JSON, unavailable media generation, and database failures.

Accessibility: Support keyboard navigation, readable contrast, semantic labels, and alternative text for evidence images.

Responsiveness: Support mobile, tablet, and desktop screen sizes.

Content safety: Generate clearly fictional cases, avoid real-person accusations, and keep mysteries non-graphic.

## 13. Acceptance criteria

The website is ready for MVP release when:

- Users can enter and submit a scenario.
- Gemini generates a valid, solvable mystery.
- Every case contains 3–5 suspects and exactly one culprit.
- Users can inspect chat, image, and CCTV-style evidence.
- All generated evidence is consistent with the mystery.
- The solution is hidden before answer submission.
- Users can select and submit one culprit.
- The backend correctly validates the submitted answer.
- Results explain the culprit and supporting clues.
- Completed cases and attempts are stored in MongoDB.
- The interface works on mobile and desktop.
- API keys and sensitive solution data are protected.
- Failed AI requests display useful errors.
